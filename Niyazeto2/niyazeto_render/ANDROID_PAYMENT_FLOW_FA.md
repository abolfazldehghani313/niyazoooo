# اتصال کلاینت اندروید به پرداخت بازارپی

در APK فقط آدرس API عمومی بک‌اند و JWT کاربر استفاده شود؛ `BAZAARPAY_AUTH_TOKEN`، کلید SMS.ir یا هیچ کلید پذیرنده‌ای نباید در اپ قرار بگیرد.

## ترتیب درخواست‌ها

1. با نشست معتبر کاربر، به `POST https://YOUR-DOMAIN/api/v1/payments/init` درخواست JSON بفرستید:

```json
{"amount":50000,"service_name":"ارتقای آگهی"}
```

هدر: `Authorization: Bearer USER_JWT` و `Content-Type: application/json`.

2. از پاسخ، `payment_id` و `payment_url` را بردارید. `payment_url` را با `Intent.ACTION_VIEW` در مرورگر یا WebView امن باز کنید.

3. پس از بازگشت کاربر به برنامه، با `GET /api/v1/payments/{payment_id}` وضعیت را استعلام کنید. به نتیجه صفحه مرورگر یا پارامترهای callback اعتماد نکنید.

4. فقط پس از تحویل واقعی خدمت/ثبت پایدار خرید، `POST /api/v1/payments/{payment_id}/commit` را با همان JWT فراخوانی کنید.

5. تا دریافت `status=paid` نتیجه را قطعی نشان ندهید. در خطای شبکه، وضعیت را دوباره استعلام کنید و درخواست جدید پرداخت نسازید.

## نمونه باز کردن لینک در Kotlin

```kotlin
val intent = android.content.Intent(
    android.content.Intent.ACTION_VIEW,
    android.net.Uri.parse(paymentUrl)
)
startActivity(intent)
```

این نمونه صرفاً لینک برگشتی از API را باز می‌کند. اتصال کامل صفحه کیف پول به این APIها نیازمند تنظیم دامنه بک‌اند و اتصال سیستم ورود فعلی اپ به JWT است؛ این مقادیر در ZIP فعلی مشخص نشده‌اند، بنابراین اپ به‌صورت خودکار به سرور ناشناخته متصل نشده است.


## پیاده‌سازی صفحه کیف پول در APK

صفحه کیف پول از داخل حساب کاربری قابل دسترسی است. آدرس API در اولین ورود در خود صفحه ثبت می‌شود؛ نمونه: `https://api.your-domain.ir` (بدون `/api/v1` در انتهای آدرس). برنامه OTP می‌گیرد، JWT را در SharedPreferences ذخیره می‌کند، موجودی و تراکنش‌ها را می‌خواند، پرداخت شارژ را می‌سازد و لینک پرداخت را با مرورگر باز می‌کند. پس از بازگشت، کاربر باید «بازگشت از درگاه؛ بررسی و ثبت پرداخت» را لمس کند. برنامه هرگز صرفاً بر اساس برگشت مرورگر کیف پول را شارژ نمی‌کند.

بک‌اند برای کیف پول جدول‌های `wallets` و `wallet_transactions` را هنگام راه‌اندازی ایجاد می‌کند. تراکنش شارژ با `payment_id` یکتا ثبت می‌شود تا درخواست تکراری باعث دوباره‌شارژ شدن نشود.
