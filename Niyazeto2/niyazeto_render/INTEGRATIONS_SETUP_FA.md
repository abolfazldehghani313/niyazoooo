# راه‌اندازی پیامک SMS.ir و پرداخت بازارپی در نیازتو

این نسخه اتصال‌ها را در **بک‌اند** پیاده‌سازی می‌کند؛ هیچ کلید محرمانه‌ای داخل APK یا کد مرورگر قرار نمی‌گیرد.

## ۱) نصب و تنظیم

در پوشه `backend`:

```powershell
python -m pip install -r requirements.txt
```

فایل `.env.example` را به `.env` کپی کنید و مقادیر واقعی را در `.env` قرار دهید. فایل `.env` را در Git یا برای دیگران ارسال نکنید.

### SMS.ir

در پنل SMS.ir یک کلید API و یک قالب ارسال سریع/Verify بسازید. نام پارامتر قالب باید با `SMSIR_OTP_PARAMETER` برابر باشد (پیش‌فرض `Code`). سپس:

```env
DEV_OTP_MODE=false
SMSIR_API_KEY=YOUR_REAL_API_KEY
SMSIR_TEMPLATE_ID=123456
SMSIR_OTP_PARAMETER=Code
```

درخواست OTP از `POST /api/v1/auth/request-otp` به `https://api.sms.ir/v1/send/verify` ارسال می‌شود. تا زمانی که `DEV_OTP_MODE=true` باشد پیامک واقعی ارسال نمی‌شود و کد در ترمینال چاپ خواهد شد.

## ۲) بازارپی SDK-Less

اطلاعات پذیرنده را از تیم بازارپی بگیرید. طبق مستندات رسمی، endpointهای این پروژه در مسیر `https://api.bazaar-pay.ir/badje/v1/` هستند:

```env
BAZAARPAY_API_BASE=https://api.bazaar-pay.ir
BAZAARPAY_API_PATH=badje/v1
BAZAARPAY_DESTINATION=YOUR_MERCHANT_DESTINATION
BAZAARPAY_AUTH_TOKEN=
BAZAARPAY_REDIRECT_URL=https://YOUR-DOMAIN/api/v1/payments/return
```

اگر برای پذیرنده احراز هویت فعال شده، مقدار توکن را در `BAZAARPAY_AUTH_TOKEN` وارد کنید؛ در غیر این صورت خالی بماند. دامنه بازگشت باید HTTPS و عمومی باشد.

### جریان پرداخت

1. کاربر با JWT معتبر `POST /api/v1/payments/init` را با `amount` (عدد صحیح طبق واحد مبلغ مورد توافق با بازارپی) و `service_name` فراخوانی می‌کند.
2. بک‌اند `checkout/init/` را صدا می‌زند و `checkout_token` و `payment_url` را در دیتابیس ذخیره می‌کند.
3. اپلیکیشن `payment_url` برگشتی را در مرورگر یا WebView باز می‌کند.
4. بازارپی کاربر را به `BAZAARPAY_REDIRECT_URL` برمی‌گرداند. سرور وضعیت را با `trace/` بررسی می‌کند؛ بازگشت مرورگر به‌تنهایی اثبات پرداخت نیست.
5. پس از اینکه سرویس/خرید واقعاً به کاربر تحویل شد، کلاینت با شناسه پرداخت `POST /api/v1/payments/{payment_id}/commit` را فراخوانی می‌کند. بک‌اند قبل و بعد از Commit وضعیت Trace را بررسی می‌کند.
6. `GET /api/v1/payments/{payment_id}` وضعیت نهایی را از بازارپی استعلام می‌کند.

**مهم:** تا وقتی `trace_status` برابر `paid_not_committed` نشده، Commit انجام نمی‌شود. برای سفارش واقعی، منطق تحویل خدمت/ثبت اعتبار باید پیش از endpoint Commit و در تراکنش پایدار پیاده شود؛ endpoint Commit را فقط پس از تحویل واقعی خدمت صدا بزنید.

## ۳) شاهکار جیبیت (تطبیق کد ملی و شماره موبایل)

این بخش بر اساس فایل OpenAPI جیبیت ارسالی پیاده‌سازی شده است. سرویس مقصد جیبیت `GET /ide/v1/services/matching` است و طبق مستندات، پشت آن سرویس شاهکار قرار دارد.

در فایل `backend/.env` کلیدها را از پنل جیبیت وارد کنید:

```env
JIBIT_API_BASE_URL=https://napi.jibit.ir
JIBIT_IDE_API_KEY=YOUR_JIBIT_API_KEY
JIBIT_IDE_SECRET_KEY=YOUR_JIBIT_SECRET_KEY
```

### جریان احراز هویت

1. کاربر در اپ با OTP وارد حساب می‌شود و JWT بک‌اند را دریافت می‌کند.
2. در صفحه «حساب کاربری ← اطلاعات شخصی و احراز هویت»، کد ملی ۱۰ رقمی را وارد می‌کند.
3. اپ `POST /api/v1/identity/shahkar/check` را با هدر `Authorization: Bearer <JWT>` و بدنه `{"national_code":"0012345679"}` فراخوانی می‌کند.
4. بک‌اند شماره موبایل حساب احراز‌شده را از رکورد کاربر می‌خواند؛ کلاینت اجازه ارسال شماره موبایل جایگزین ندارد. سپس بک‌اند با توکن Jibit، درخواست GET به `/ide/v1/services/matching?nationalCode=...&mobileNumber=...` می‌فرستد و `X-TRACK-ID` یکتا قرار می‌دهد.
5. نتیجه `matched=true/false` به اپ برمی‌گردد و در صفحه نمایش داده می‌شود. مقدار کد ملی در دیتابیس نیازتو ذخیره نمی‌شود.

نمونه پاسخ بک‌اند:

```json
{
  "matched": true,
  "message": "کد ملی و شماره موبایل با یکدیگر تطابق دارند.",
  "track_id": "..."
}
```

توکن‌های `accessToken` و `refreshToken` فقط در حافظه فرایند بک‌اند نگهداری می‌شوند. چون مستندات OpenAPI ارسالی زمان انقضای توکن را مشخص نکرده است، بک‌اند هنگام دریافت خطای `403 forbidden` ابتدا مسیر Refresh را امتحان می‌کند و در صورت شکست، توکن جدید می‌گیرد؛ خطای `daily_limit.reached` باعث تمدید بی‌مورد توکن نمی‌شود. با راه‌اندازی مجدد سرور، جفت توکن جدید به‌صورت خودکار با API Key و Secret Key ساخته می‌شود.

**نکته اجرایی:** ابتدا کاربر باید در بخش کیف پول با شماره موبایل واقعی خود و OTP وارد شده و آدرس API بک‌اند را تنظیم کرده باشد؛ صفحه شاهکار از همان نشست و شماره موبایل استفاده می‌کند. کلیدهای Jibit را داخل APK، کد Kotlin، پنل مدیریت یا Git قرار ندهید.

## ۴) APIهای اضافه‌شده

- `POST /api/v1/payments/init` ایجاد چک‌اوت (نیازمند JWT کاربر)
- `GET /api/v1/payments/return?token=...` صفحه بازگشت مرورگر و استعلام Trace
- `GET /api/v1/payments/{payment_id}` استعلام پرداخت متعلق به کاربر
- `POST /api/v1/payments/{payment_id}/commit` نهایی‌سازی پس از تحویل خدمت
- `POST /api/v1/auth/request-otp` ارسال Verify از SMS.ir یا حالت توسعه
- `POST /api/v1/identity/shahkar/check` تطبیق کد ملی با شماره موبایل حساب واردشده (نیازمند JWT کاربر)
- پنل مدیریت: وضعیت پیکربندی SMS.ir، بازارپی و شاهکار جیبیت و فهرست آخرین پرداخت‌ها در بخش تنظیمات

## ۵) قبل از انتشار

- مقدارهای `JWT_SECRET_KEY` و `ADMIN_PASSWORD` را عوض کنید.
- `DEV_OTP_MODE=false` فقط پس از تنظیم و آزمایش قالب SMS.ir.
- HTTPS فعال کنید و `BAZAARPAY_REDIRECT_URL` را با دامنه واقعی جایگزین کنید.
- کلیدهای واقعی `JIBIT_IDE_API_KEY` و `JIBIT_IDE_SECRET_KEY` را فقط در `.env` سرور قرار دهید و یک استعلام با حساب آزمایشی مجاز انجام دهید.
- واحد مبلغ، سقف/کف و وضعیت فعال بودن احراز هویت بازارپی را از پذیرنده تأیید کنید.
- برای محیط پرترافیک، OTP را از حافظه به Redis/DB منتقل و محدودیت نرخ، تعداد تلاش، انقضا و ثبت لاگ امن اضافه کنید.
- فایل `.env` حاوی کلیدهاست؛ هرگز آن را در ZIP عمومی، Git یا APK قرار ندهید.

## ۶) اتصال کیف پول اپلیکیشن

صفحه «حساب کاربری ← کیف پول و تراکنش‌ها» در نسخه اندروید به API بک‌اند متصل شده است:

- آدرس عمومی سرور را در صفحه کیف پول وارد کنید (فقط دامنه HTTPS در انتشار نهایی).
- ورود با OTP از مسیرهای `/api/v1/auth/request-otp` و `/api/v1/auth/verify-otp` انجام می‌شود و JWT در حافظه محلی برنامه نگهداری می‌شود.
- موجودی از `GET /api/v1/wallet` و گردش حساب از `GET /api/v1/wallet/transactions` خوانده می‌شود.
- شارژ از `POST /api/v1/payments/init` ساخته و لینک بازارپی در مرورگر باز می‌شود. پس از برگشت به اپ، دکمه «بررسی و ثبت پرداخت» وضعیت را از سرور می‌گیرد.
- اعتبار کیف پول فقط پس از Trace موفق و وضعیت `paid_committed` اضافه می‌شود. شناسه پرداخت در جدول گردش حساب یکتا است تا شارژ تکراری ایجاد نشود.

### تنظیمات لازم برای استفاده واقعی

در `backend/.env` مقدار `DEV_OTP_MODE=false`، کلید و قالب واقعی SMS.ir، اطلاعات پذیرنده بازارپی، `JWT_SECRET_KEY` قوی و `BAZAARPAY_REDIRECT_URL` با دامنه HTTPS خودتان را تنظیم کنید. سپس بک‌اند را مجدداً راه‌اندازی کنید. اگر `DEV_OTP_MODE=true` باشد، کد OTP فقط در لاگ سرور چاپ می‌شود و پیامک واقعی ارسال نمی‌شود.

واحد مبلغ کیف پول در رابط کاربری تومان است؛ واحدی که به API بازارپی ارسال می‌شود باید با واحد توافق‌شده برای پذیرنده شما یکسان باشد. قبل از دریافت وجه واقعی، مبلغ آزمایشی را در محیط مورد تأیید پذیرنده بررسی کنید.

## تنظیم کلیدها از داخل پنل مدیریت

در نسخه جدید، وارد مسیر «تنظیمات و راهنما ← اتصال سرویس‌ها» شوید. کلیدهای SMS.ir، بازارپی و جیبیت را در فرم مربوط به هر سرویس وارد کنید و گزینه «ذخیره و تست» را بزنید. تنظیمات روی خود میزبان بک‌اند در فایل `backend/.env` ذخیره و در همان پردازش اعمال می‌شوند؛ نیازی به قراردادن کلیدها در APK یا ارسال آن‌ها در چت نیست.

- تست SMS.ir یک پیامک OTP واقعی به شماره‌ای که برای تست وارد می‌کنید می‌فرستد و ممکن است از اعتبار پنل پیامکی مصرف کند.
- تست جیبیت، دریافت توکن دسترسی را بررسی می‌کند.
- تست بازارپی یک نشست پرداخت آزمایشی ایجاد می‌کند؛ این کار به‌تنهایی پرداخت را انجام نمی‌دهد. برای نهایی‌کردن تراکنش، لینک پرداخت نباید باز یا تأیید شود.
- حساب کاربری سیستم‌عامل که بک‌اند را اجرا می‌کند باید اجازه نوشتن در پوشه `backend` را داشته باشد.
